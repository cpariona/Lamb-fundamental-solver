# Focused fitting validation suite

This document describes the maintained validation suite for fitting backends.

## Purpose

Smoke tests check that maintained APIs, adapters, and minimal synthetic cases run without breaking.

The focused fitting validation suite is different. It checks whether implemented fitting backends can recover known synthetic parameters within explicit tolerances.

The suite is intentionally separate from:

```matlab
run_all_smoke_tests
```

because fitting validation may be slower, especially for atlas-based model families.

## Main entrypoint

Run:

```matlab
clear functions
rehash toolboxcache
startup
run_fit_validation_tests
```

This executes:

```matlab
test_fit_validation_rayleigh_lamb
test_fit_validation_mrlfe
test_fit_validation_mrlfe_hidden_params
test_fit_validation_ae_iop_hgo
test_fit_validation_ae_iop_hgo_hidden_params
```

The combined summary is assigned to the MATLAB base workspace as:

```matlab
FitValidationSummary
```

## Shared assertion helper

The validation scripts use:

```matlab
assertFitRecovery
```

This helper checks:

```text
finite fitted parameter value
relative parameter error below tolerance
RMSE below tolerance
minimum number of valid fitted points
finite fitted Cp on valid points
```

It also returns a summary table row with:

```text
TestName
TrueValue
FittedValue
RelativeError
RMSE_mps
ValidPoints
Identifiability
Optimizer
```

## Rayleigh-Lamb validation cases

`test_fit_validation_rayleigh_lamb` validates:

```text
RL_A0_mu_exact
RL_A0_thickness_exact
RL_A0_mu_perturbed
```

The first two use exact synthetic data generated by the same maintained Rayleigh-Lamb evaluator. The third adds a small deterministic perturbation to the synthetic phase speed.

The perturbed case is not intended to prove statistical robustness. It only checks that the optimizer does not collapse under small deterministic deviations from the exact forward model.

## mRLFE validation cases

`test_fit_validation_mrlfe` validates:

```text
mRLFE_A0Like_mu_exact
mRLFE_A0Like_mu_perturbed
mRLFE_A0Like_mu_app_adapter
```

The first mRLFE validation target remains conservative:

```text
branch: A0Like
free parameter: mu
etaS: 0 Pa*s
```

`test_fit_validation_mrlfe_hidden_params` currently validates A0Like thickness recovery with hidden/fixed material parameters in the stable zero-viscosity fitting path. It does not validate `etaS` recovery.

mRLFE FitTool route-specific contracts are validated separately by:

```matlab
run_mrlfe_fit_public_solver_tests
```

## AE IOP/HGO validation cases

`test_fit_validation_ae_iop_hgo` validates:

```text
AE_atlasA0_mu_exact
AE_atlasA0_mu_app_adapter
```

`test_fit_validation_ae_iop_hgo_hidden_params` validates hidden/fixed parameter handling for the AE fitting path.

The AE validation uses only the official atlas output:

```matlab
result.Cp
result.validCp
```

from:

```matlab
solveAcoustoelasticIOPHGOBranch
```

It explicitly checks that the synthetic validation case does not rely on fallback branch selection and that the branch policy remains:

```text
atlasA0
```

Diagnostic branches such as `identityA0Diagnostic`, `raw_branch1`, or branch-family candidates are not accepted as fitting outputs.

## Current limitations

This validation phase does not yet validate:

```text
mRLFE etaS fitting as a parameter-recovery case
mRLFE thickness fitting outside the stable zero-viscosity hidden-parameter case
AE IOP fitting
AE thickness fitting
AE multiparameter fitting
weighted fitting using standardError_Cp_mps
real experimental data fitting
parameter covariance or uncertainty estimates
```

Those should be added as separate validation cases only after their synthetic behavior is stable.

## Recommended validation order

After fitting-related changes, run:

```matlab
clear; clc; close all;
startup
run_all_smoke_tests
run_fit_validation_tests
```

For mRLFE FitTool route or plotting behavior, also run:

```matlab
run_mrlfe_fit_public_solver_tests
run_mrlfe_route_integrity_tests
```

For FitTool interaction changes that do not alter solvers, run:

```matlab
run_fit_tool_interaction_tests
```

This focal runner checks:

```text
parameter summary versus global fit quality summary
manual experimental table row helpers
axis limit validation
explicit requested fitted-curve evaluation
presence of the new FitTool controls
```

If the focused suite fails, run individual groups:

```matlab
test_fit_validation_rayleigh_lamb
test_fit_validation_mrlfe
test_fit_validation_mrlfe_hidden_params
test_fit_validation_ae_iop_hgo
test_fit_validation_ae_iop_hgo_hidden_params
```
