# Focused fitting validation suite

This document describes the validation suite added after the first Rayleigh-Lamb, mRLFE, and AE IOP/HGO fitting backends were implemented.

## Purpose

The smoke tests check that the maintained APIs, adapters, and minimal synthetic cases run without breaking.

The focused fitting validation suite is different. It checks whether the implemented fitting backends can recover known synthetic parameters within explicit tolerances.

The suite is intentionally separate from:

```matlab
run_all_smoke_tests
```

because fitting validation may be slower, especially for AE IOP/HGO atlas-based fitting.

## Main entrypoint

Run:

```matlab
clear functions
rehash toolboxcache
startup
run_fit_validation_tests
```

This executes:

```matlab
test_fit_validation_rayleigh_lamb
test_fit_validation_mrlfe
test_fit_validation_ae_iop_hgo
```

The combined summary is assigned to the MATLAB base workspace as:

```matlab
FitValidationSummary
```

## Shared assertion helper

The validation scripts use:

```matlab
assertFitRecovery
```

This helper checks:

```text
finite fitted parameter value
relative parameter error below tolerance
RMSE below tolerance
minimum number of valid fitted points
finite fitted Cp on valid points
```

It also returns a summary table row with:

```text
TestName
TrueValue
FittedValue
RelativeError
RMSE_mps
ValidPoints
Identifiability
Optimizer
```

## Rayleigh-Lamb validation cases

`test_fit_validation_rayleigh_lamb` validates:

```text
RL_A0_mu_exact
RL_A0_thickness_exact
RL_A0_mu_perturbed
```

The first two use exact synthetic data generated by the same maintained Rayleigh-Lamb evaluator. The third adds a small deterministic perturbation to the synthetic phase speed.

The perturbed case is not intended to prove statistical robustness. It only checks that the optimizer does not collapse under small deterministic deviations from the exact forward model.

## mRLFE validation cases

`test_fit_validation_mrlfe` validates:

```text
mRLFE_A0Like_mu_exact
mRLFE_A0Like_mu_perturbed
mRLFE_A0Like_mu_app_adapter
```

The first mRLFE validation target remains conservative:

```text
branch: A0Like
free parameter: mu
etaS: 0 Pa*s
```

Viscous fitting of `etaS` is not yet part of the maintained validation suite.

## AE IOP/HGO validation cases

`test_fit_validation_ae_iop_hgo` validates:

```text
AE_atlasA0_mu_exact
AE_atlasA0_mu_app_adapter
```

The AE validation uses only the official atlas output:

```matlab
result.Cp
result.validCp
```

from:

```matlab
solveAcoustoelasticIOPHGOAtlasBranch
```

It explicitly checks that the synthetic validation case does not rely on fallback branch selection and that the branch policy remains:

```text
atlasA0
```

Diagnostic branches such as `identityA0Diagnostic`, `raw_branch1`, or branch-family candidates are not accepted as fitting outputs.

## Current limitations

This validation phase does not yet validate:

```text
mRLFE etaS fitting
mRLFE thickness fitting
AE IOP fitting
AE thickness fitting
AE multiparameter fitting
weighted fitting using standardError_Cp_mps
real experimental data fitting
parameter covariance or uncertainty estimates
```

Those should be added as separate validation cases only after their synthetic behavior is stable.

## Recommended validation order

After fitting-related changes, run:

```matlab
run_core_smoke_tests
run_gui_smoke_tests
run_acoustoelastic_smoke_tests
run_mrlfe_smoke_tests
```

Then run the focused fitting validation suite:

```matlab
run_fit_validation_tests
```

If the focused suite fails, run individual groups:

```matlab
test_fit_validation_rayleigh_lamb
test_fit_validation_mrlfe
test_fit_validation_ae_iop_hgo
```
