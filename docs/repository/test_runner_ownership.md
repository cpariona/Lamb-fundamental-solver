# MATLAB test runner ownership and validation tiers

Last reviewed: 2026-07-14

This document is the maintained ownership contract for the MATLAB tests under
`tests/`. The machine-readable companion is
`analysis/test_inventory/test_runner_ownership.csv`, regenerated by
`buildTestOwnership` after `buildTestInventory` parses the current runner
graph.

## Ownership rules

- Every maintained test has exactly one direct canonical runner.
- Aggregate runners call focused owners; they do not call the same test again.
- A test may be reachable from several aggregates without having multiple
  direct owners.
- Manual-only entries are explicit and have no normal runner edge.
- Runtime tiers describe validation purpose. Measured time is evidence, never
  a hardware-dependent pass/fail threshold.
- The nine compatibility wrappers and the standalone
  `run_main_gui_export_tests` command remain public.

The implemented graph represents 104 tests: 103 have one direct canonical
runner and one is explicitly manual. There are 27 canonical runner names, zero
unowned maintained tests, zero multiple canonical owners, and zero tests with
multiple executable direct runner memberships.

## Public validation tiers

| Tier | Command | Current static reach | Purpose |
| --- | --- | ---: | --- |
| quick contract | `run_quick_contract_tests` | 14 tests | paths, metadata, validation, imports, interaction helpers, public defaults/validation |
| quick smoke | `run_quick_smoke_tests` | 47 tests | quick contracts plus GUI adapters and representative AE/mRLFE executions |
| numerical regression | `run_numerical_regression_tests` | 17 tests | snapshots, result schema, branch consistency, selected fitting regressions, AE and production-core solver regression |
| extended integration | `run_extended_integration_tests` | 40 tests | profile matrix, requested-curve solving, broad fitting validation, public-solver consumer characterization |
| performance | `run_performance_and_benchmark_tests` | 2 tests | descriptive fit-grid and production-core timing evidence |

The quick commands contain no known multi-minute characterization, performance
test, 36-case matrix, or stale benchmark. `run_quick_smoke_tests` is the
recommended routine developer command. Runtime observations for the aggregate
commands are recorded separately in
`docs/repository/test_suite_runtime_evidence.md`.

The mRLFE public-solver consumer runners remain explicit extended or
characterization owners because they preserve distinct contracts and include
measured 100-271 second cases. Splitting every single characterization into a
one-test runner would not improve command clarity.

## Execution-profile ownership

`run_execution_profile_contract_tests` directly owns normalization, model
resolvers, cleanup, surface metadata, and state-transition contracts.
`run_gui_execution_profile_tests` owns current GUI behavior and cross-surface
integration. `run_execution_profile_integration_tests` owns fitted-curve
metadata and the 36-case validation matrix.

The historical cleanup, infrastructure, surface, and end-to-end runner names
remain compatible aggregates over these owners. Their transitive sets are now
broader and consistently layered; they no longer call the same tests as
sibling runners. `run_execution_profile_diagnostics_tests` owns only diagnostic
formatting.

## Before/after overlap

The baseline graph had 149 edges and eight tests with multiple executable
direct runner memberships. The ownership graph has 203 edges because it
contains the new hierarchy, but the number of tests with multiple executable
direct memberships is zero. Repeated reachability through public aggregates is
intentional aggregation, not sibling direct duplication.

## Regeneration and integrity checks

```matlab
clear functions
rehash toolboxcache
startup
addpath(fullfile(pwd, 'analysis', 'test_inventory'))

[inventory, edges] = buildTestInventory('WriteCsv', true);
ownership = buildTestOwnership('WriteCsv', true, 'ValidateActual', true);

assert(height(ownership) == 104)
assert(nnz(ownership.ManualOnly) == 1)
assert(all(strlength(ownership.CanonicalRunner) > 0))
```

The parser is static. Dynamic calls and MATLAB path resolution remain subject
to the limitations documented in `analysis/test_inventory/README.md`, so the
new quick and focused runners must also be executed in MATLAB.
